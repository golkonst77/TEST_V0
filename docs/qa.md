# Вопросы по архитектуре - BA Copilot

## Архитектурные вопросы

### 1. База данных

**Вопрос**: Стоит ли полностью отказаться от Supabase в пользу локального JSON?
- **Плюсы**: Простота, отсутствие сетевых зависимостей, быстрая работа
- **Минусы**: Ограниченная масштабируемость, отсутствие ACID транзакций
- **Рекомендация**: Использовать гибридный подход - JSON для отзывов, Supabase для пользователей и настроек

**Вопрос**: Как обеспечить синхронизацию данных между JSON и Supabase?
- **Варианты**: 
  1. Периодическая синхронизация через cron
  2. Синхронизация при изменениях через API
  3. Использование только одного источника истины

### 2. Парсинг отзывов

**Вопрос**: Как обрабатывать изменения в структуре Яндекс.Карт?
- **Проблема**: Селекторы могут измениться, что сломает парсер
- **Решение**: 
  1. Мониторинг изменений
  2. Несколько резервных селекторов
  3. Автоматические тесты

**Вопрос**: Стоит ли добавить кэширование парсинга?
- **Варианты**:
  1. Кэширование на уровне файлов
  2. Кэширование на уровне API
  3. Периодическое обновление данных

### 3. Производительность

**Вопрос**: Как оптимизировать загрузку 39 отзывов?
- **Текущее решение**: Клиентская пагинация
- **Альтернативы**:
  1. Серверная пагинация
  2. Виртуализация списка
  3. Ленивая загрузка

**Вопрос**: Нужно ли добавить CDN для статических файлов?
- **Плюсы**: Быстрая загрузка, снижение нагрузки на сервер
- **Минусы**: Дополнительная сложность, стоимость

### 4. Безопасность

**Вопрос**: Как защитить административную панель?
- **Текущее состояние**: Отсутствует аутентификация
- **Планы**: Supabase Auth с ролями пользователей

**Вопрос**: Безопасно ли хранить JSON файлы в public папке?
- **Риски**: Публичный доступ к данным
- **Решение**: Переместить в приватную папку, добавить middleware

### 5. Масштабируемость

**Вопрос**: Как система будет работать с тысячами отзывов?
- **Проблемы**: 
  1. Размер JSON файлов
  2. Время загрузки
  3. Память браузера

**Вопрос**: Нужна ли база данных для отзывов?
- **Аргументы за**: 
  - Поиск и фильтрация
  - Аналитика
  - Масштабируемость
- **Аргументы против**: 
  - Сложность
  - Сетевые зависимости

## Технические вопросы

### 1. Python интеграция

**Вопрос**: Стоит ли переписать парсер на JavaScript?
- **Плюсы**: Единая экосистема, проще деплой
- **Минусы**: Меньше библиотек для парсинга, сложнее обработка HTML

**Вопрос**: Как обрабатывать ошибки Python скрипта?
- **Текущее решение**: Try-catch в Node.js
- **Улучшения**: Детальное логирование, retry механизм

### 2. API дизайн

**Вопрос**: Нужна ли версионирование API?
- **Текущее состояние**: Нет версионирования
- **Рекомендация**: Добавить `/api/v1/` префикс

**Вопрос**: Как стандартизировать ответы API?
- **Текущее состояние**: Разные форматы ответов
- **Планы**: Единый формат с success/error полями

### 3. Тестирование

**Вопрос**: Какие тесты нужны в первую очередь?
- **Приоритеты**:
  1. API endpoints
  2. Парсинг отзывов
  3. Компоненты React
  4. Интеграционные тесты

**Вопрос**: Как тестировать Python скрипт?
- **Варианты**:
  1. Unit тесты с мок HTML
  2. Интеграционные тесты с реальными данными
  3. E2E тесты
