# Дневник разработки

## 2025-01-07

### Наблюдения
- Режим технического обслуживания в админке был настроен, но не работал
- Middleware в Next.js не может быть асинхронным, что ограничивает возможности проверки режима обслуживания
- Нужно было найти альтернативный способ проверки режима обслуживания

### Решения
- Создан компонент `MaintenancePage` с красивым дизайном страницы технического обслуживания
- Создан API endpoint `/api/maintenance` для проверки статуса режима обслуживания
- Создан компонент `MaintenanceWrapper` для проверки режима в layout (клиентская сторона)
- Добавлено исключение для админки из проверки режима обслуживания
- Обновлен `app/layout.tsx` для использования `MaintenanceWrapper`

### Проблемы
- Изначально пытался использовать асинхронный middleware, но это не поддерживается в Next.js
- Нужно было найти способ проверки режима обслуживания без блокировки рендеринга
- Решение через клиентский компонент может вызывать мигание контента при загрузке

### Технические детали
- Использован `usePathname()` для определения текущего маршрута
- API endpoint использует существующую функцию `getSettings()` из `settings-store.ts`
- Страница обслуживания включает контакты, время работы и ссылки на социальные сети
- Добавлены правильные HTTP заголовки (503 Service Unavailable, Retry-After)
