## [2025-08-30] - Система управления видимостью секций по устройствам

### Наблюдения
- Пользователь запросил возможность отдельно управлять видимостью секций для мобильных и десктопных устройств
- Текущая система `homepage-sections.json` поддерживала только одно значение статуса на секцию
- Необходимо было создать систему определения типа устройства на клиентской стороне

### Решения
1. **Структура данных**: Изменил формат `homepage-sections.json` с простого `string` на объект с `desktop` и `mobile` полями
2. **Определение устройства**: Создал хук `useDeviceType` с пороговым значением 1024px (mobile ≤1024px, desktop ≥1024px)
3. **API обновление**: Модифицировал `useHomepageSections` для поддержки параметра `deviceType`
4. **Админка**: Создал новую страницу `/admin/visibility` с переключателями для каждого типа устройства
5. **Интеграция**: Обновил главную страницу для использования новой системы

### Проблемы
- **Нет критических проблем** - система работает стабильно
- **Возможное улучшение**: Добавить поддержку планшетов как отдельного типа устройства

### Технические детали
- **Порог устройства**: 1024px (стандарт для мобильных/десктопных устройств)
- **Производительность**: Мгновенное применение изменений без перезагрузки
- **UX**: Интуитивный интерфейс с цветовой индикацией (синий для десктопа, зеленый для мобильных)

## [2025-08-30] - Улучшение UI квиза

- Пользователь жаловался на плохую читаемость
- Необходимо было увеличить размеры без изменения логики

### Решения
1. **Карточки опций**: Увеличил padding с `p-2` до `p-6`
2. **Радио-кнопки и чекбоксы**: Увеличил размеры с `w-3.5 h-3.5` до `w-5 h-5`
3. **Шрифты**: Увеличил размеры с `text-base` до `text-lg` для опций и с `text-xl` до `text-2xl` для заголовков
4. **Отступы**: Увеличил spacing между элементами

### Проблемы
- **Решено**: Все элементы стали более читаемыми
- **Решено**: Сохранена вся функциональность

### Технические детали
- **Изменения**: Только CSS классы Tailwind
- **Логика**: Не изменена
- **Результат**: Улучшенный UX без потери функциональности

## [2025-08-30] - Исправление проблем с F5 и GSAP

### Наблюдения
- Сайт "висел" при обновлении страницы (F5)
- Проблемы с загрузкой GSAP анимаций
- Система управления секциями не работала корректно

### Решения
1. **GSAP загрузка**: Перенес `require('gsap')` внутрь `useEffect` для клиентской загрузки
2. **Система секций**: Восстановил правильную работу `useHomepageSections` с API
3. **Верхнее меню**: Добавил `id` атрибуты для всех секций
4. **Загрузка**: Добавил индикатор загрузки на главную страницу

### Проблемы
- **Решено**: Сайт стабильно работает при F5
- **Решено**: GSAP анимации загружаются корректно
- **Решено**: Система управления секциями функционирует

### Технические детали
- **Причина F5 проблемы**: SSR конфликт с GSAP
- **Решение**: Клиентская загрузка GSAP
- **Результат**: Стабильная работа сайта

## Общие наблюдения

### Архитектурные решения
1. **Клиентская загрузка**: GSAP и другие библиотеки загружаются только на клиенте
2. **Fallback система**: Локальные JSON файлы как резервные источники данных
3. **Модульная структура**: Компоненты разделены по функциональности
4. **API-first подход**: Все данные загружаются через API endpoints

### Проблемы и решения
1. **SSR конфликты**: Решены через клиентскую загрузку
2. **Кодировка**: Использование stdin/stdout для передачи данных
3. **Производительность**: Оптимизация через кэширование и lazy loading
4. **UX**: Постоянные улучшения на основе обратной связи

### Технический стек
- **Frontend**: Next.js 14, React 18, TypeScript
- **Styling**: Tailwind CSS, Material UI
- **Backend**: Supabase, Node.js API routes
- **Интеграции**: WhatsApp API, Yandex Maps
- **Анимации**: GSAP
